# 用語集

システムで使用する用語の定義です。
設計書・コード内で用語を統一するために参照してください。

## ビジネス用語

| # | ビジネス用語 | 説明 |
|---|-------------|------|
| 1 | 内部ID | トレーニング機関内で使用する会員の識別番号。DBの主キーとは別に、業務上で使う番号として保持する。新規登録時は現在の最大値+1で自動採番、編集画面で手動変更も可能 |
| 2 | 所感 | トレーナーが記録する所見・気づき。トレーナー間で共有するが会員には非開示。お客様に開示する「トレーナーからのノート」（No.21）と対をなす |
| 3 | 音声ファイル | 録音またはアップロードされた音声の実ファイル。音声記録の一種で、文字起こしの入力となる |
| 4 | 文字起こし | 音声ファイルをテキストに変換すること。Whisper APIを使用 |
| 5 | 要約 | 文字起こしテキストをAIで短くまとめたもの。Claude APIを使用 |
| 6 | 電話番号 | 会員の連絡先。緊急時に最初に連絡する番号 |
| 7 | 電話番号（予備） | 会員の連絡先のうち 2 つ目。1 つ目がつながらないときに使う。携帯・自宅・家族の番号など、用途は問わない |
| 8 | メールアドレス登録用 URL | トレーナーが発行し、会員自身にメールアドレスを登録してもらう URL。有効期限は発行から 3 日。**この期限が初回設定完了までの全体の期限**となる |
| 9 | ログイン用リンク | 登録されたメールアドレスに届く、初回設定用のリンク。**リンクを開くと会員がログインした状態になる**（ログインさせる働きを持つ）。有効期限は独立して持たず、**対応するメールアドレス登録用 URL の期限をそのまま引き継ぐ**（お客様がメールアドレスを登録した時点から数え直さない） |
| 10 | 初回設定 | 会員がログイン用リンクから、パスワードと基本情報、および**愛犬（トレーニー）の情報**を設定すること。**愛犬の名前は必須**（詳細は screen-design.md S-1403 / requirements.md 6-15-5 参照） |
| 11 | メールアドレス確認リンク | メールアドレス変更画面（S-1409）からメールアドレスを変更する際、**新しいアドレスに送る**リンク。**メールアドレスを切り替えるだけの役割**で、ログインさせる働きは持たない。ログイン用リンク（No.9）とは性質が異なる別のもの。他のトークンとは無関係に発行されるため、**独立した有効期限**（3 日）を持つ |
| 12 | メールアドレスなし | 会員の状態のひとつ。メールアドレスが未登録で、有効なメールアドレス登録用 URL もない状態。メールアドレス登録用 URL を発行するとメールアドレス登録待ちに遷移する。**画面のバッジでは「未登録」と表示する**（**2026-10 変更**。それまで「なし」と表示していたが、状態がより伝わる文言に差し替えた。バッジはラベル「メールアドレス」の内側にあるため、対象を重ねずに状態だけを短く表す） |
| 13 | メールアドレス登録待ち | 会員の状態のひとつ。有効なメールアドレス登録用 URL が発行済みで、まだお客様がメールアドレスを登録していない状態。お客様がメールアドレスを登録すると初回設定待ちに遷移する。**画面のバッジでは「登録待ち」と表示する**（バッジはラベル「メールアドレス」の内側にあるため、対象を重ねずに状態だけを短く表す） |
| 14 | 初回設定待ち | 会員の状態のひとつ。メールアドレスは登録済みだが、パスワードがまだ設定されていない状態。お客様が初回設定を完了すると利用中に遷移する。**（判定ルール：メールアドレスがあり、かつ有効なメールアドレス登録用 URL もあるケースはこちらを優先）** |
| 15 | 利用中 | 会員の状態のひとつ。メールアドレスとパスワードの両方が登録済みで、会員が閲覧機能にログインできる状態。トレーナーはこの状態で会員詳細画面の「登録を削除」ボタン（旧「メールアドレスを削除」）から登録を消せる（初回設定待ちでも同ボタンから消せる） |
| 16 | 登録情報 | ログイン中のお客様が、自分の登録内容（氏名・住所・電話番号・メールアドレスなど）を確認・変更する画面群。**登録情報画面（S-1406、確認画面）** を入口として、そこから登録情報の変更（S-1411）・パスワードの変更（S-1410）・メールアドレスの変更（S-1409）の 3 つの独立画面へ遷移する。メールアドレスの変更は新しいアドレスへ「メールアドレス確認リンク」（No.11）を送り、リンクが開かれた時点で切り替える |
| 17 | パスワード再設定リンク | パスワードを忘れたお客様がログイン画面（S-1401）の「パスワードを忘れた方」から申し込みを行った際、登録アドレスに届く**新しいパスワードを設定するためのリンク**。**ログインさせる働きは持たない**（ログイン用リンク No.9 との違い）。**メールアドレスも変えない**（メールアドレス確認リンク No.11 との違い）。他のトークンとは無関係に発行されるため、**独立した有効期限**（3 日）を持つ |
| 18 | マイページ | お客様が自分のトレーニング記録やメディアを見るためにログインして使う場所を指す、お客様向けの呼び名。トレーナーがお客様に「マイページに登録してもらいます」のように口頭で使う言葉でもある。**プロダクト名（`config('app.client_portal_name')`、既定値「トレーニング記録」）とは別の呼称**で、ログイン画面などのワードマークにはプロダクト名を出し、案内の文章の中では「マイページ」と呼ぶ。トレーナー側の操作ボタン（「マイページ登録案内を発行」「マイページ登録案内を表示」）や、印刷ページ・お客様側の案内文でこの呼び名を使う |
| 19 | マイページ登録案内 | お客様にマイページへ登録してもらうために渡す一連の案内（QR コード・URL・手順・有効期限を載せた紙面／画面）。トレーナーが S-0305 で「マイページ登録案内を発行」を押すと、内部的に「メールアドレス登録用 URL」（No.8）が作られ、その URL を載せた S-0307 印刷ページとして「マイページ登録案内を表示」ボタンから開ける。**「メールアドレス登録用 URL」がトークンそのものの識別**であるのに対し、**「マイページ登録案内」はお客様に渡す案内の呼び名**として使い分ける。発行済みの案内は、状態が「メールアドレス登録待ち（期限内）」のとき「マイページ登録案内を取消」で取り消せる（6-3-7） |
| 20 | トレーニング記録 | データの単位。日付・担当・ノート（No.21）・所感（No.2）・メディアを含む記録全体を指す。画面名・メニュー名・エンティティ名でもこの語を使う（「トレーニング記録一覧画面」「トレーニング記録詳細画面」など） |
| 21 | トレーナーからのノート | トレーニング記録（No.20）の中で、お客様に見せる文章（`record_content`）。設計書内では短く「ノート」と呼ぶ。お客様に非開示の「所感」（No.2）と対をなし、事実を客観的に記録する。**画面に出るラベルは「トレーナーからのノート」で統一**し、括弧補足は付けない |
| 22 | 会員 | トレーニング機関に登録されたお客様（飼い主）。マイページの利用有無を問わない（メールでのやりとりをしないお客様も含む）。内部名は client（テーブル名・クラス名等は client のまま） |
| 23 | トレーニー | トレーニングの対象。当面は犬。会員に1対多で紐づく（複数頭は稀）。画面表記もそのまま「トレーニー」で統一する。**トレーニング記録（No.20）は会員単位であり、トレーニー単位ではない**（どのトレーニーの話かは記録の本文に書く。この方針は「トレーニー別に記録を分けると入力が煩雑になる」というトレーナーの要望に基づく）。将来の対象拡張を見据え、テーブル名・クラス名は犬に限定しない `trainees` を使う |
| 24 | 計測値 | トレーニーごとの計測記録（現状は体重のみ）。トレーニング記録（No.20）とは独立したデータで、`training_records` とは紐付けない。基本的に毎朝計測、1日2回計測することもある。4日間・8日間コースなど預かり期間ごとに計測日が飛ぶ運用に対応する |
| 25 | コース | 4日間・8日間コースなど、トレーニングの預かり期間の総称。**システムはコースをエンティティとして持たない**（コース期間外の計測に対応できなくなるため）。計測値のグラフは**横軸を時間軸**にし、コース期間の切れ目は「計測日時が離れている＝横軸上で空白ができる」形で自然に表れる（線は 1 本の連続した折れ線で結ぶ。詳細は screen-design.md S-1402「横軸を時間軸に変更した経緯」参照）。当初は「一定日数以上空いたら線を分割する」方式だったが、2026-09 に廃止した（間隔の不正確さのほうが問題だったため） |
| 26 | トレーニング日 | トレーニング記録の日付（`training_records.training_date`）。**トレーナー側画面のラベル・列見出し・検索条件で「トレーニング日」に統一**する（**2026-09**）。従前は画面ごとに「日付」「最終記録日」などとばらついていた。計測値の「**計測日**」（No.24 参照）と区別するため、また記録の種別（`training_types`）が 2026-09 に廃止されて `training_records` に入るのがすべてトレーニングの記録という前提に揃ったため、DB カラム名 `training_date` と一致する呼称に統一した。**会員の最終のトレーニング記録日**（会員一覧 S-0304 の列名・検索条件）は **「最終トレーニング日」**。**会員側の画面ではラベル語を出さず**、「○月○日（曜）の記録」（詳細画面）や日付ブロック（縦帯・横帯）で日付そのものを見出しとして扱う流儀（詳細は client-portal-design-plan.md §6 の書き換え表参照）。詳細な適用範囲は screen-design.md §2-6 参照 |

※ api-design.md / db-schema.md / architecture.md / client-portal-design-plan.md の本文に残る「クライアント」は、お客様を指す場合「会員」と同義（画面表記を「会員」に変更した際、内部向け設計書の本文は未置換）。

## 技術用語

| 用語 | 説明 |
|------|------|
| Whisper API | OpenAIが提供する音声文字起こしAPI。日本語を含む多言語に対応 |
| Claude API | Anthropicが提供する大規模言語モデルAPI。要約に使用（Haiku 4.5） |
| 非同期処理 | 処理の完了を待たずに次の操作に進める方式。文字起こし・要約の処理に使用し、ブラウザのタイムアウトを防ぐ |
| キュー（Job） | Laravelの非同期処理の仕組み。バックグラウンドでAPIの処理を実行する |
| MediaRecorder API | ブラウザ標準のAPIで、マイクからの音声をリアルタイムで録音する機能 |
| API（Application Programming Interface） | 外部システムとのデータ受け渡し口 |
