# バッチ設計書: トレーニング記録管理システム

## 1. 全バッチ共通要素

### 1-1. 実行の仕組みと時刻（**2026-10 変更**）

自動で動かすバッチは、Laravel のスケジュール（`bootstrap/app.php` の `withSchedule`）にまとめて登録する。サーバーの cron は、`schedule:run` を毎分動かす 1 行だけにする（手順はアプリ構築手順書 第11段階）。登録したバッチと時刻は `php artisan schedule:list` で確かめられる。

変更の理由：サーバーの移行のとき、cron に直接書いていたバッチのうちバックアップしか移されず、ほかのバッチが止まっていたため。スケジュールにまとめておけば、バッチが増えても cron を触らずに済む。

| 時刻（毎日） | ID | バッチ | コマンド |
|------|------|------|------|
| 2:00 | B-0201 | 長期間未ログインアカウントロックバッチ | `trainers:lock-inactive` |
| 2:10 | B-0202 | 未使用アカウントロックバッチ | `trainers:lock-unused` |
| 2:20 | B-0101 | 音声ファイル削除バッチ | `audio-records:delete-expired` |
| 2:30 | B-0301 | バックアップバッチ | `db:backup` |

- 時刻は 10 分ずつずらし、バッチが重ならないようにする。どのバッチにも `withoutOverlapping()` を付け、前の回が終わっていなければ次の回を動かさない。
- 時刻の基準は Asia/Tokyo（`config/app.php` の `timezone`）。
- 各バッチのログ（開始・結果・エラー）は、アプリのログ（`storage/logs/`）に出す。B-0301 のコンソールへの出力は、`storage/logs/cron-backup.log` に追記する。
- B-0302 リストアバッチは、手動でだけ動かす（スケジュールに登録しない）。

### 1-2. 日数の設定と、有効な範囲の外のときの動き（**2026-10 変更**）

日数を使うバッチ（B-0101・B-0201・B-0202）は、日数を `.env` で設定する（画面からは設定しない）。`.env` に書いていなければ初期値で動く。コマンド引数（`--days`）を指定したときは、引数を優先する（手で動かすとき用。スケジュールからは引数を付けずに呼ぶ）。

| 環境変数 | 設定キー | 初期値 | 有効な範囲 | バッチ |
|------|------|------|------|------|
| `COUNSELOR_LOCK_INACTIVE_DAYS` | `batch.lock_inactive_days` | 30 | 1〜90日 | B-0201 |
| `COUNSELOR_LOCK_UNUSED_DAYS` | `batch.lock_unused_days` | 7 | 1〜90日 | B-0202 |
| `AUDIO_RETENTION_DAYS` | `batch.audio_retention_days` | 7 | 1〜30日 | B-0101 |

- 設定の名前は、ほかのシステムと共通にするため `COUNSELOR_…` のままにしている（このシステムでの対象はトレーナー）。
- 使う日数が有効な範囲の外（0・負の数・上限を超える・整数でない）のときは、そのバッチは何もせず（ロック・削除をせず）、どのバッチで・どの値が範囲の外だったかをエラーとしてログに残し、失敗の終了コードで終わる。範囲の端には丸めない（設定の誤りに気づけるようにするため。たとえばロックの日数が誤って 0 になると、全員がロックされかねない）。
- `.env` を変えたあとは `php artisan config:clear` を実行する。

## 2. バッチ詳細

**記載範囲**:
- 本章では、本システムが提供する全バッチを列挙する。
- 全バッチとは、要件定義書（docs/requirements.md）の8章「バッチ一覧」で挙げられているバッチを指す。
- 各バッチの入力・処理フロー・出力の把握を目的とする。

**参照ルール**:
- 各バッチの概要・提供機能・実行方式・実行権限は、要件定義書（docs/requirements.md）の8章「バッチ一覧」で管理している。本書では同じバッチIDを使用しているため、バッチIDで突き合わせて参照すること。

**記載する項目**: 各バッチについて、以下の項目を記載する。

- **入力**（必須）: バッチが受け取る入力情報。コマンド引数、対象データ、設定値など。
- **処理フロー**（必須）: 入力を受け取ってから出力に至るまでの処理ステップを、番号付きで順に記載する。
- **出力**（必須）: バッチが生成する出力。ファイル、ログ、DB更新、通知など。
- **備考**: 業務的・運用的に重要な特記事項がある場合のみ記載。


### 2-1. 音声ファイル容量管理

#### B-0101 音声ファイル削除バッチ

##### 入力

**コマンド引数**

| 引数 | 必須 | 説明 |
|------|------|------|
| 保存期間 |  | 音声ファイルの保存期間（日数）。省略時は設定値（`AUDIO_RETENTION_DAYS`、初期値7日。1-2）を使う。有効な範囲は1〜30日の整数 |

##### 処理フロー

1. 「保存期間」を取得する（コマンド引数の指定、なければ設定値）。有効な範囲（1〜30日の整数）の外の場合は、削除せずにエラーをログに残し、失敗で終了する（**2026-10 変更**。1-2）。
2. 音声記録が登録された日時から「保存期間」を過ぎた音声ファイルを削除し、音声記録のレコードから音声ファイルへの紐づけを解除する（文字起こし・要約テキストは保持）。

##### 出力

ログ：成功時は処理サマリ、失敗時はエラー内容を出力する。

### 2-2. トレーナー管理

#### B-0201 長期間未ログインアカウントロックバッチ

##### 入力

**コマンド引数**

| 引数 | 必須 | 説明 |
|------|------|------|
| 未ログイン日数 |  | しきい値となる日数。省略時は設定値（`COUNSELOR_LOCK_INACTIVE_DAYS`、初期値30日。1-2）を使う。有効な範囲は1〜90日の整数 |

##### 処理フロー

1. 「未ログイン日数」を取得する（コマンド引数の指定、なければ設定値）。有効な範囲（1〜90日の整数）の外の場合は、ロックせずにエラーをログに残し、失敗で終了する（**2026-10 変更**。1-2）。
2. 以下の条件すべてを満たすトレーナーアカウントを抽出する：
   - 有効である
   - ロックされていない
   - システム管理者ではない
   - 一度以上ログインしている（最終ログイン日時がある）
   - 最終ログイン日時から「未ログイン日数」を過ぎている
3. 抽出したアカウントをロックする。ただし、ロックすると有効な管理者が 1 人以下になる場合は、その管理者をロックしない。

##### 出力

ログ：成功時は処理サマリ、失敗時はエラー内容を出力する。

### 2-3. バックアップ管理

#### B-0301 バックアップバッチ

##### 入力

**コマンド引数**

なし

**設定値**

バックアップ動作設定：

| 設定キー | 環境変数 | 必須 | 説明 |
|----------|----------|------|------|
| `backup.directory` | `BACKUP_DIRECTORY` | ● | バックアップファイルの保存先ディレクトリ |
| `backup.encryption_key` | `BACKUP_ENCRYPTION_KEY` | ● | バックアップファイルの暗号化鍵（パスフレーズ） |
| `backup.mysqldump_path` | `MYSQLDUMP_PATH` |  | mysqldump コマンドのパス（未設定時は `mysqldump`） |
| `backup.openssl_path` | `OPENSSL_PATH` |  | openssl コマンドのパス（未設定時は `openssl`） |

DB 接続情報（ホスト・ポート・ユーザー・パスワード・データベース名）は `config('database.default')` で解決した既定接続の設定を参照する。バックアップ固有の設定値としては持たない。

バックアップ用オブジェクトストレージ接続設定（S3 互換。現在の既定構成は Cloudflare R2）：

| 項目名 | 必須 | 説明 |
|--------|------|------|
| `BACKUP_STORAGE_ENDPOINT` | ● | ストレージのエンドポイント URL |
| `BACKUP_STORAGE_BUCKET` | ● | バケット名 |
| `BACKUP_STORAGE_ACCESS_KEY_ID` | ● | アクセスキー ID |
| `BACKUP_STORAGE_SECRET_ACCESS_KEY` | ● | シークレットキー |
| `BACKUP_STORAGE_REGION` |  | リージョン（任意、既定 `auto`。R2 では未指定でよい。さくら等に差し替える場合に設定） |

##### 処理フロー

1. データベースを mysqldump で取得し、パイプで openssl AES-256-CBC + PBKDF2 に渡して暗号化したうえで、`backup.directory` 配下に保存する。
  - ファイル名は `{db_name}_YYYYMMDD_HHMMSS.sql.enc` 形式とする。
2. 1. で作成したバックアップファイルを、バックアップ用オブジェクトストレージのバケット（`BACKUP_STORAGE_BUCKET`）にコピーする。
  - オブジェクトキーはファイル名と同じ：`{db_name}_YYYYMMDD_HHMMSS.sql.enc`
3. 1. で作成したバックアップファイルを `backup.directory` から削除する。

##### 出力

ログ：成功時は処理サマリ、失敗時はエラー内容を出力する。

#### B-0302 リストアバッチ

##### 入力

**コマンド引数**

| 引数 | 必須 | 説明 |
|------|------|------|
| ファイル名 | ● | バックアップ用オブジェクトストレージ上のバックアップファイル名。例：`{db_name}_YYYYMMDD_HHMMSS.sql.enc` |

**設定値**

リストア動作設定：

| 設定キー | 環境変数 | 必須 | 説明 |
|----------|----------|------|------|
| `backup.directory` | `BACKUP_DIRECTORY` | ● | バックアップファイルの保存先ディレクトリ |
| `backup.encryption_key` | `BACKUP_ENCRYPTION_KEY` | ● | バックアップファイルの暗号化鍵（パスフレーズ） |
| `backup.mysql_path` | `MYSQL_PATH` |  | mysql コマンドのパス（未設定時は `mysql`） |
| `backup.openssl_path` | `OPENSSL_PATH` |  | openssl コマンドのパス（未設定時は `openssl`） |

DB 接続情報（ホスト・ポート・ユーザー・パスワード・データベース名）は `config('database.default')` で解決した既定接続の設定を参照する。バックアップ固有の設定値としては持たない。

バックアップ用オブジェクトストレージ接続設定（S3 互換。現在の既定構成は Cloudflare R2）：

| 項目名 | 必須 | 説明 |
|--------|------|------|
| `BACKUP_STORAGE_ENDPOINT` | ● | ストレージのエンドポイント URL |
| `BACKUP_STORAGE_BUCKET` | ● | バケット名 |
| `BACKUP_STORAGE_ACCESS_KEY_ID` | ● | アクセスキー ID |
| `BACKUP_STORAGE_SECRET_ACCESS_KEY` | ● | シークレットキー |
| `BACKUP_STORAGE_REGION` |  | リージョン（任意、既定 `auto`。R2 では未指定でよい。さくら等に差し替える場合に設定） |

##### 処理フロー

1. リストア対象の「ファイル名」を表示して、Y/N で確認を求める。
2. バックアップ用オブジェクトストレージのバケット（`BACKUP_STORAGE_BUCKET`）から指定された「ファイル名」のオブジェクトを取得し、`backup.directory` 配下に保存する。
3. 2. でダウンロードしたバックアップファイルを openssl で復号し、パイプで mysql に渡してデータベースを復元する。
4. 2. でダウンロードしたバックアップファイルを `backup.directory` から削除する。

##### 出力

ログ：成功時は処理サマリ、失敗時はエラー内容を出力する。
